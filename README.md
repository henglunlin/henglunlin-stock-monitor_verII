# 台股監控器 — React 版

用 React 前端取代 Streamlit，主攻**訊號顯示密度與排版自由度**。
後端沿用原本的 Python 邏輯，只是把呼叫者從 Streamlit 換成 FastAPI。

舊的 Streamlit 版留在 [`henglunlin-stock-monitor-FUBAN`](https://github.com/henglunlin/henglunlin-stock-monitor-FUBAN) 並行運作，這個 repo 不影響它。

---

## 架構

```
富邦 Neo WebSocket ─┐
                    ├─→ Render（FastAPI + 富邦 SDK）─→ WebSocket ─→ Vercel（React）
GitHub Actions ─────┘         └─→ Telegram
（排程掃描、資料同步）
```

| 元件 | 放哪 | 費用 |
|---|---|---|
| React 前端 | Vercel | 免費 |
| FastAPI + 富邦 SDK | Render（**Region 選 Singapore**） | 免費 |
| 排程掃描、資料儲存 | GitHub | 免費 |

**月成本 NT$0，不需要開自己的電腦。**

## 快速開始

**後端**

```bash
python -m venv .venv
.venv\Scripts\activate                 # Windows；Mac/Linux 用 source .venv/bin/activate

pip install -r server/requirements.txt

# 富邦 SDK 分平台，要另外裝：
pip install .\fubon_neo-2.2.8-cp37-abi3-win_amd64.whl        # Windows
# pip install ./fubon_neo-2.2.8-...-manylinux_2_17_x86_64...whl   # Linux/Mac

cp .env.example .env          # 填入 FUBON_PFX_BASE64
python scripts/selftest.py    # 一個指令確認環境齊全
uvicorn server.main:app --reload --port 8000
```

> **為什麼富邦 SDK 要分開裝**：它的 whl 是分平台的，而 pip 在評估環境標記
> 之前就會先去找檔案，沒辦法用 `; sys_platform == 'linux'` 把兩個平台寫進
> 同一份 requirements。所以本機用 `server/requirements.txt`，
> Render 用 `server/requirements-render.txt`（多帶 Linux 版 whl）。

**前端**（另開一個終端機）

```bash
cd web
npm install
npm run dev                   # http://localhost:5173
```

開發時 Vite 的 proxy 會把 `/api` 與 `/ws` 轉發到 `localhost:8000`，
所以本機不會踩到 CORS。

## 版面

儀表板是主畫面，其餘都是浮動視窗——看盤時九成的時間你問的是「哪一類在動」，
而不是「第 87 檔的 KD 是多少」。原版把表格放主位、儀表板擠在上面，
等於把一成的需求擺在九成前面。

```
狀態列  ← 連線／富邦／tick 數／暫停中提示
工具列  ← 手動更新、啟用自動更新、慢線秒數、Telegram、定時推送、全部股票、設定、登入
加權指數走勢（可收合）
┌────────────────────────────────────────┐
│  漲幅儀表板（滿版，自己捲）                │
│  19 張分類卡片，可依分類順序／達標比例／檔數排序 │
└────────────────────────────────────────┘
        ↓ 點卡片
   分類清單（浮動視窗，虛擬捲動表格）
        ↓ 點任一列
   個股詳情（浮動視窗，盤中走勢＋開高低＋指標＋訊號＋買入區間）
```

關掉個股詳情會回到它的來源清單，不是回到儀表板——不然每看一檔就要重點一次分類。

**表格活在浮動視窗裡是刻意的。** 之前把儀表板跟表格塞進同一個捲動容器，
virtualizer 預設假設清單從容器頂端開始，上面墊著的儀表板高度沒被計入，
表頭下方就出現一大塊空白。浮動視窗天生擁有自己的捲動區，結構上不可能再犯。

## 走勢欄畫的是「今天」

表格的「走勢」欄預設畫**當日盤中走勢**，不是近 30 日收盤。虛線是昨收，
沒有它讀不出「現在在平盤上還是下」——迷你圖是自動縮放的，畫的是相對起伏。

資料哪裡來：富邦每筆 tick 進來時，後端在記憶體裡累積一條**每 20 秒一個點**的序列
（每檔上限 900 點，換日自動清空）。慢線每次送整列時附上取樣過的 40 點，
前端再用快線的報價把最後 20 秒補上，所以線尾跟價格欄是同步跳的。

**這條序列不打任何 REST。** 對 193 檔各叫一次富邦分鐘 K 一定撞 429，
所以分鐘 K 只在「點開單檔詳情」時呼叫，一次一檔。

尚未登入富邦、盤前或假日時沒有盤中資料，走勢欄自動退回近 30 日收盤——
否則開盤前整欄空白會看起來像壞掉。

## 盤中訊號與跑馬燈

畫面頂端常駐一條「盤中訊號」，**三欄並列共九則、不橫向捲動**。

會捲動的字讀不了：你不能掃視，只能等它捲過來。所以「動」只發生在新訊號進來的
那一刻——插到最前面、其餘往後推、閃一下。每一則都能點，直接開該檔詳情。
三欄是因為一列一則會浪費掉寬螢幕，而訊號密集時三則根本不夠看；視窗變窄會
自動降成兩欄、單欄。右邊的「全部訊號」展開完整事件流（時間倒序、可依種類篩選）。

| 訊號 | 條件 | 冷卻 | 上跑馬燈 |
|---|---|---|---|
| 🔴 漲停 | 觸及依升降單位算出的實際漲停價 | 整天一次 | ✅ |
| 🔺 即將漲停 | 漲幅 ≥ 7.5% | 30 分 | ✅ |
| 🚀 瞬間拉抬 | 量比＋外盤占比＋短線漲幅＋突破高點或自低點拉抬 | 45 秒 | ✅ |
| 📈 瞬間反彈 | 現價 / 今日最低 − 1 ≥ 3% | 4 分 | ✅ |
| 🟢 跌停 / 🔻 即將跌停 | 同漲停，反向 | — | ❌ 只進事件流 |
| ⚠️ 預警 | 拉抬扣掉突破條件 | 60 秒 | ❌ 只進事件流 |

### 三道閘門，缺一個跑馬燈就會變成洪流

193 檔配每秒一次的偵測，沒有節流的話一分鐘內畫面就沒法看。三道防線沿用
`盤中訊號監控器.py` 累積出來的做法：**signal_key 去重**、**每檔每種訊號各自冷卻**、
**30 秒優先權窗**（同一檔 30 秒內來了更高優先的，低優先的直接吞掉）。

其中兩處刻意跟原版不同，都是離線模擬跑出來的：

1. 原版的「預警」**沒有冷卻**（只有進場訊號有）。在 19 檔上撐得住，193 檔會炸，
   所以這裡每一種訊號都一定帶冷卻。
2. 「已觸及漲停價」必須跟「即將漲停」分成**兩個優先等級**。共用同一級的話，
   一檔在 30 秒內從 7.5% 直接鎖漲停時，觸價那則會被優先權窗當成重複訊號吞掉——
   你只收到「快漲停了」，永遠收不到「漲停了」。

### 訊號沒出來時，要分得出是「真的沒訊號」還是「壞了」

`GET /api/debug/detector`（設定視窗裡也看得到）會攤開每個條件當下的實際值：
現價、昨收、今日最低、反彈%、算出來的漲跌停價、有沒有武裝，以及每輪掃描耗時。

`scan_ms` 同時是「Render 免費方案的 0.1 CPU 夠不夠」的量測依據——實測數字見下一節。

## 🚀 瞬間拉抬怎麼判斷

四個條件**同時**成立才算：

| 條件 | 預設 | 說明 |
|---|---|---|
| 量能放大 | 量比 ≥ 1.1x | 「預估整桶量」÷ 前一桶量。預估量 = 目前累積量 ÷ 已過秒數 × 30，所以第 5 秒就看得出放大，不必等 30 秒結束 |
| 主動買盤 | 外盤占比 ≥ 55% | 沒有主動買盤的量增只是換手 |
| 短線急拉 | 2秒 0.8% / 5秒 0.8% / 10秒 1.2% / 30秒 2.0% 任一 | |
| 位置正確 | 摸到 60 秒高點（×0.998）**或** 自 60 秒低點拉抬 ≥ 2% | 沒有這個，橫盤放量也會報 |

少了「位置正確」就降級成 ⚠️ 預警，只進事件流不上跑馬燈。

參數全部照搬 `盤中訊號監控器.py` 的 `DEFAULT_ENTRY_*`，設定視窗裡可以調。

### 資料存法是為了 512MB / 0.1 CPU 特別設計的

原版每檔留 1500 筆價格點 + 1500 筆成交明細，每筆是含 datetime 的 dict。
那支只跑 19 檔很寬裕，**我們是 193 檔**：

```
193 × 3000 筆 × 約 280 bytes  ≈  162 MB     ← 直接把 Render 免費方案撐爆
```

改成**四條平行的 float 陣列**（ts / price / vol / buyvol，時間戳存 epoch 秒），
窗口從 400 秒縮到 120 秒（拉抬最長只回看 60 秒，夠用）：

```
193 × 1500 筆 × 4 × 8 bytes  ≈  9.3 MB      ← 少 17 倍，功能一分沒少
```

CPU 也調過。第一版是「複製整個視窗出來，再用 Python 迴圈掃四五遍」，
193 檔全滿的最壞情況量到 **p50 60ms**——每秒一次就是 0.1 CPU 的六成，
一定跟慢線和 SDK 接收執行緒搶起來。改成三件事之後降到 **p50 9.7ms**：

1. **bisect 二分搜尋**找區間邊界，取代線性掃描
2. **切片加總** `sum(vol[i:j])`，取代逐筆累加的迴圈；外盤量靠寫入時就分流的
   `buyvol` 陣列，同樣一個 `sum` 解決（多 8 bytes/筆換掉整個熱點）
3. **`max()`/`min()` 切片**取代自己寫的高低點迴圈

再加上「最近一整個桶都沒成交就直接跳過」的早退，盤中實際情境
（193 檔中約 25 檔在跳）是 **p50 2.9ms**，等於 0.1 CPU 的 3%。

### 內外盤是 fail-closed 的，所以一定要能診斷

抓不到內外盤時外盤占比算不出來，拉抬**永遠不會觸發，而且不會報錯**。
`/api/debug/detector` 會把每一項條件當下的實際值攤開（量比、外盤占比、
2/5/10/30 秒漲幅、追蹤窗高低點、哪一項卡住），設定視窗裡也看得到。
selftest 有一項專門驗證這個 fail-closed 行為。

## 漲跌停價是算出來的，不是用百分比估

台股漲跌停是先算 ±10% 再依股價級距取整，取整後的實際漲幅**不會剛好是 10%**：

```
昨收 33.05 → 漲停 36.35（實際 +9.98%）   昨收 105 → 漲停 115.5（實際 +10.00%）
```

用「漲幅 > 9.5%」判斷會在邊緣一直判錯。`core/detectors.py` 的 `calc_limit_prices()`
原樣沿用原版的升降單位表（0.01 / 0.05 / 0.1 / 0.5 / 1 / 5）。

## 三個開關的語意，跟原版不完全一樣

原版那個「刷新秒數 3 秒」是**整頁重跑**的間隔，而整頁重跑同時做了兩件事：
抓最新報價、重算所有指標與訊號。新架構把這兩件事拆開了，所以一個開關變成兩個：

| 新架構 | 控制什麼 | 對應原版的哪一半 |
|---|---|---|
| 啟用自動更新 | 前端是否套用推送進來的資料。暫停時畫面凍結，WebSocket 仍連著，解除立刻跳回最新 | 「要不要一直跳」 |
| 慢線秒數 | 後端重算指標與訊號的間隔，會真的送到後端存起來 | 「多久重算一次」 |
| 快線間隔（設定裡） | 報價推送的節流間隔，預設 300ms | 原版沒有這個粒度 |

快線沒有「關閉」選項，因為它幾乎不花成本：只推這段時間內變動過的股票，
沒變動就完全不發包。關掉省不到什麼，卻會讓價格停在舊值。

## 這個設計的兩個關鍵決定

### 一、快慢兩線

原本 Streamlit 每 3 秒把所有東西重算一次——報價、指標、22 個訊號、整張表重繪。
檔數一多就是這樣拖垮的。現在拆開：

| | 間隔 | 內容 |
|---|---|---|
| **快線** | 300ms | 只推這段時間內變動過的報價，沒變動就完全不發 |
| **慢線** | 20s | 重算技術指標、跑訊號、比對目標價 |

前端收到快線只更新價格那一格，收到慢線才更新整列。這是「只有變動的格子會閃」
與「幾百檔不卡」的來源。

### 二、心跳不是可選的

Render 免費方案 15 分鐘沒有 inbound 流量就休眠，而官方明確說明
**WebSocket 訊息算 inbound 流量**。前端每 30 秒送一次 `ping`，
這是盤中服務不會睡著的唯一機制，拿掉的話午休回來就會斷線。

## 已知限制（原版就有，刻意維持一致）

**沒有國定假日行事曆** — `get_history_cutoff_date()` 只用星期幾判斷，
春節端午會算錯一天。搬家階段維持與原版相同行為，才能比對新舊版。

**盤後模式 + db 且 db 尚無今日資料時，漲跌幅顯示 0%** — 當下價與昨收都取到
同一筆歷史收盤。與原版邏輯一致，不是新架構造成的。

## 分類編輯器

工具列的「🛠️ 分類編輯」。左欄分類（新增／改名／刪除／上下排序），
右欄該分類的股票膠囊，加一個查得到代碼與名稱的快速新增框——打「台積」或
「2330」都找得到，Enter 加入；貼上多筆逗號或換行分隔的代碼會一次全部解析。

跟原版兩個刻意的差別：

1. **明確按儲存。** 原版按下「刪除分類」就直接寫進磁碟並 rerun，誤點救不回來。
   這裡所有編輯先改在草稿上，右上角顯示「有未儲存的變更」，關視窗會攔截。
   後端真正寫檔前還會自動留一份備份快照。
2. **GitHub 同步預設開。** Render 免費方案沒有持久磁碟，不同步的話重新部署
   分組就會還原成 repo 裡那份。沒設 `GITHUB_TOKEN` 時會安靜退回本機模式並說明一次，
   不會每次存檔都跳紅字。

存檔後會**同步訂閱**：新增的訂閱、移除的退訂。之前只訂閱不退訂，所以刪掉的股票
富邦還是會一直推，`subscribed_count` 只增不減直到重啟。退訂需要訂閱 id
（從訂閱確認訊息裡撈，原本被丟掉了）；拿不到 id 時走「斷線重連只訂需要的」的退路，
代價是約 2–3 秒沒有報價。
